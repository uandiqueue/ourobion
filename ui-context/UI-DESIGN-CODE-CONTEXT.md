## What Is a UI Design Code File?

A **UI design code file** in this project is a raw HTML prototype exported from **Google Stitch** — a generative UI design tool that produces functional, browser-renderable HTML screens.

These files are **not production code**. They are **design blueprints** — fully visual and interactive in a browser, but not yet integrated into the Flutter app.

---

## Where These Files Come From

Each file in `ui-context/` is generated by Stitch using:

- The **Biotope design system** (colours, typography, spacing tokens defined in the Tailwind config embedded in the file)
- The **Material Design 3 (M3)** component language
- **Manrope** as the primary typeface (via Google Fonts)
- **Material Symbols Outlined** for iconography

The Tailwind config block inside each file defines the full design token set — colours, border radii, spacing, and font sizes — that must be **translated into Flutter theme tokens** when implementing.

---

## What Each File Contains

| Element | Description |
|---|---|
| `tailwind.config` script | Full design token set (colours, spacing, typography) |
| `<header>` | Top navigation bar for the screen |
| `<main>` | The scrollable body content of the screen |
| `<section>` blocks | Logical UI groupings (e.g. Wellbeing, Biological Output) |
| Fixed `<div>` at bottom | Sticky action button (e.g. Submit) |
| Inline styles | Overrides for sliders, scrollbars, and body min-height |

## How to Use These Files

### Step 1 — Preview in a Browser
Open the file directly in any browser to see the intended design. This is the **source of truth** for the visual layout.

### Step 2 — Map to the Correct Flutter Module

Each screen belongs to a module. Save your Flutter implementation under the matching `ui/` folder:

| Screen Content | Flutter Module Path |
|---|---|
| Auth / Sign-in / Consent | `src/lib/modules/m1_core/ui/` |
| Daily Log / Gut / Behaviour | `src/lib/modules/m2_self_report/ui/` |
| Passive Health / Wearables | `src/lib/modules/m3_passive_health/ui/` |
| Environment / Outbreak | `src/lib/modules/m4_environmental/ui/` |
| Insights / Discovery Cards | `src/lib/modules/m5b_insight_engine/ui/` |
| Streaks / Rewards | `src/lib/modules/m6_engagement/ui/` |

### Step 3 — Translate Tokens to Flutter

Map the Tailwind design tokens to Flutter `ThemeData`. Key mappings:

| Tailwind Token | Flutter Equivalent |
|---|---|
| `primary` `#3c6752` | `ColorScheme.primary` |
| `on-surface` `#191c1c` | `ColorScheme.onSurface` |
| `surface-container-lowest` `#ffffff` | `ColorScheme.surfaceContainerLowest` |
| `outline-variant` `#c1c8c2` | `ColorScheme.outlineVariant` |
| `font-family: Manrope` | `GoogleFonts.manrope()` in `TextTheme` |
| `headline-sm` 20px / 600 | `TextStyle(fontSize: 20, fontWeight: FontWeight.w600)` |
| `label-md` 12px / 600 | `TextStyle(fontSize: 12, fontWeight: FontWeight.w600)` |
| `body-md` 16px / 400 | `TextStyle(fontSize: 16, fontWeight: FontWeight.normal)` |

### Step 4 — Name the Dart File Correctly

Use **lowercase with underscores** (snake_case) for the file name, ending in `_screen.dart` or `_widget.dart`.

**Example:**
```
ui-context/ui-design-code          ← Stitch HTML prototype
src/lib/modules/m2_self_report/ui/daily_log_screen.dart   ← Flutter implementation
```

## Rules

1. **Never import from `ui-context/` in Flutter code.** These are reference-only files.
2. **Do not rename or modify Stitch files** — treat them as locked design specs.
3. **Always preview in a browser** before beginning Flutter implementation.
4. **Design tokens in the Tailwind config are the source of truth** — if a colour or spacing value is unclear, refer to the `tailwind.config` block in the file.
